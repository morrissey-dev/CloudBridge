# CloudBridge V2.0 — integration plan

**Status:** integration preparation only. This document does not declare a V2.0 release. The application package remains `1.9.0` until the release gates are complete.

## Purpose

V2.0 is intended to be a stability, integration, and release-readiness milestone—not another feature-only update. It should consolidate the V1.1–V1.9 work while preserving the existing Git history, learner progress formats, and the current live deployment until explicit approval.

## Git baseline and branch

- Archived baseline commit: `33a3a3c` (`Improve CloudBridge learning continuity`).
- Prepared branch: `integration/cloudbridge-v2.0-release-prep`.
- The original five commits are retained as ancestors.
- Nine new version-by-version commits were prepared from the supplied V1.1–V1.9 source snapshots and incremental patches.
- Each prepared version was compared against its matching source ZIP after normalizing line endings; the snapshots matched.
- These new commits are a **reconstructed integration history**, not recovered copies of historical V1.1–V1.9 commits. They currently use a neutral local preparation identity. Review or re-author them before publishing if you want the commits attributed to your GitHub identity.
- Nothing has been pushed to GitHub and no Netlify deployment has been changed.

## Safely bring the branch into the original repository (Windows PowerShell)

1. Download `CloudBridge-V2.0-integration-prep.bundle` and place it somewhere accessible. Do not replace your repository folder with a source ZIP.
2. Open PowerShell in your existing CloudBridge repository and inspect the working tree:

   ```powershell
   git status
   git log --oneline -5
   ```

3. If you have local edits, commit or stash them first. Export CloudBridge learning progress from the app if you have data you need to keep.
4. Fetch the prepared branch from the bundle (adjust the bundle path if needed):

   ```powershell
   git fetch C:\path\to\CloudBridge-V2.0-integration-prep.bundle `
     refs/heads/integration/cloudbridge-v2.0-release-prep:refs/heads/integration/cloudbridge-v2.0-release-prep
   ```

5. Inspect the branch before switching:

   ```powershell
   git log --oneline --decorate -12 integration/cloudbridge-v2.0-release-prep
   git diff --stat main...integration/cloudbridge-v2.0-release-prep
   ```

6. Switch to the branch only after confirming your local repository contains the same baseline history:

   ```powershell
   git switch integration/cloudbridge-v2.0-release-prep
   ```

7. Run the full local checks in the next section. Do not push, merge into `main`, or deploy until the checks and manual review are complete.

### If your repository has moved on

This prepared branch is based on archived commit `33a3a3c`. If your current `main` has newer commits or the diff shows unexpected local changes, stop before merging or deploying. Rebase/merge the prepared work against your current branch only after reviewing the differences. Do not use `--force` to bypass conflicts.

## Local validation commands

Run these from the project root on a clean machine with the supported Node.js version:

```powershell
npm ci
npm test
npm run typecheck
npm run build
npm run dev
```

A successful `npm test` run is not a substitute for a successful clean production build. If `npm ci` or `npm run build` fails, do not deploy.

## Deployment safety

- Keep the existing Netlify site and `main` unchanged until approval.
- Use a branch preview or a separate preview deployment first.
- Confirm existing learning progress, exam history, and exported backups remain readable.
- Keep an export of important learner progress before updating a live environment.
- Have a rollback path to the currently deployed build.
